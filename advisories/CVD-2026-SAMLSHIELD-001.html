CVD-2026-SAMLSHIELD-001: SAML Temporal Validation Bypass via NaN Timestamp Comparison and Missing SubjectConfirmationData/@NotBefore & Multi-Subject Validation in stytchauth/samlshield

Researcher: Serhii Shunko (@ccsimplyspolit)

Repository: stytchauth/samlshield

HackerOne Program: twilio (Scope ID 1047285 — github.com/stytchauth/samlshield)

Affected Component: src/validate.ts (lines 956-1022)

Weakness / Severity: CWE-290 / CWE-347 · High (CVSS 7.7)

Summary

I identified a SAML temporal and structural validation bypass in `stytchauth/samlshield` (`src/validate.ts`, lines 956-1022). In `validateTimestamps()`, `new Date(...).getTime()` is evaluated on `Conditions/@NotBefore`, `Conditions/@NotOnOrAfter`, and `SubjectConfirmationData/@NotOnOrAfter` without checking `Number.isNaN(...)`. Because JavaScript comparisons with `NaN` (`now + CLOCK_SKEW_TOLERANCE_MS < NaN` and `now - CLOCK_SKEW_TOLERANCE_MS > NaN`) always evaluate to `false`, any unparseable or non-ISO timestamp string silently bypasses expiration checks. Additionally, `validateTimestamps()` omits checking `SubjectConfirmationData/@NotBefore` and does not enforce a single `<saml:Subject>` element.

Suggested Remediation Patch

Impact

Applications relying on `samlshield` as a pre-validation layer before downstream SAML consumption can accept assertions with malformed temporal bounds, future-dated `SubjectConfirmationData/@NotBefore` attributes, or ambiguous multi-`Subject` structures.
