CVD-2026-NOTION-MCP-001: Unrestricted Local File Upload in HttpClient.prepareFileUpload() and Cross-Tenant Session Hijacking in Token-Passthrough Mode in makenotion/notion-mcp-server

Researcher: Serhii Shunko (@ccsimplyspolit)

Repository: makenotion/notion-mcp-server

HackerOne Program: notion (Scope ID 1047345 — Notion MCP (makenotion/notion-mcp-server))

Affected Component: src/openapi-mcp-server/client/http-client.ts (lines 104-141) & scripts/start-server.ts (lines 116-199, 216-237)

Weakness / Severity: CWE-22 / CWE-73 / CWE-384 · High (CVSS 8.6)

Summary

I identified two high-severity security defects in `makenotion/notion-mcp-server` (`@notionhq/notion-mcp-server`): (1) in `src/openapi-mcp-server/client/http-client.ts` (lines 104-141), `HttpClient.prepareFileUpload()` passes caller- or LLM-supplied `multipart/form-data` binary parameter values directly to `fs.createReadStream(filePath)` without path canonicalization, base-directory restriction, or symbolic link rejection, enabling arbitrary local file read and exfiltration to Notion via prompt injection; and (2) in `scripts/start-server.ts` (lines 116-199, 216-237), when `--enable-token-passthrough` is enabled for multi-tenant HTTP deployments, `transports[sessionId]` is keyed solely by `mcp-session-id` without binding or verifying the caller's `Notion-Token` header on subsequent `POST /mcp`, `GET /mcp`, or `DELETE /mcp` requests.

Impact

An attacker who can influence LLM tool arguments via indirect prompt injection (e.g., content inside a Notion page or database) can read arbitrary local files from the MCP host and upload them into a Notion workspace, or hijack another tenant's active Notion MCP session in shared HTTP token-passthrough deployments.
