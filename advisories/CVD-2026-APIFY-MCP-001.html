CVD-2026-APIFY-MCP-001: Unredacted Token Leakage via traceId & Case-Sensitive / OAuth Token Redaction Bypass in resolveStoreSearchTracking (src/utils/mcp_clients.ts)

High (CVSS 7.6) CWE-200 / CWE-290 GitHub CNA PVR: apify/apify-mcp-server
Target Repository: apify/apify-mcp-server (commit d3bee2ec2c, 2026-10-25T08:17:15Z)
Affected Component: src/utils/mcp_clients.ts (lines 11-47)
Researcher: Serhii Shunko (@sshunko / @ccsimplyspolit, ORCID 0009-0002-4183-0361)

1. Summary

During a defensive static source audit of `https://github.com/apify/apify-mcp-server` (`main` branch, commit `d3bee2ec2c` / `826e128e55`, pushed `2026-10-25T08:17:15Z`), I identified token redaction and origin-spoofing defects in `resolveStoreSearchTracking()` (`src/utils/mcp_clients.ts:11-47`), introduced in commit `826e128e55` (*'feat: Send trace id and use case with Apify Store searches (#1650)'*): 1. **Missing Token Redaction and Format Validation on `traceId` (`CWE-200`, `src/utils/mcp_clients.ts:36, 44`)**: Any MCP client that declares `clientInfo: { name: 'apify-ai' }` in `initialize` is granted `REQUEST_ORIGIN.APIFY_AI` (`getRequestOriginForClient()`, line 22). In `resolveStoreSearchTracking()`, `traceId` is read from `meta?.['com.apify/traceId']` or `mcpSessionId` (`line 36`) and forwarded directly into `GET /v2/store?_traceId=...` URL query parameters (which land in API access logs) and telemetry `trace_id` **without any token redaction or character-set validation**. 2. **Case-Sensitive `APIFY_API_TOKEN_REGEX` & Unredacted `apify_mcp_` / `Bearer` Tokens in `useCase` (`CWE-200`, `src/utils/mcp_clients.ts:11, 38-41`)**: `APIFY_API_TOKEN_REGEX = /apify_api_[A-Za-z0-9]+/g` (`line 11`) lacks the case-insensitive `/i` flag and only matches `apify_api_`, failing to redact uppercase/mixed-case `APIFY_API_...` tokens, `apify_mcp_...` OAuth/MCP tokens, or `Bearer ...` authorization tokens before sending `_useCase` in plaintext `GET /v2/store` URL query strings.

2. Root Cause Analysis

- **`src/utils/mcp_clients.ts:11-47`**:
```typescript

    requestOrigin: REQUEST_ORIGIN,
    meta: Record<string, unknown> | undefined,
    mcpSessionId: string | undefined,
): NonNullable<ApifyClient['storeSearchTracking']> {
    const asString = (value: unknown) => (typeof value === 'string' ? value.trim() : '');

              .slice(0, STORE_USE_CASE_MAX_LENGTH)
        : '';
```

- **BEFORE PATCH**: `tracking_before('apify_api_SecretInTrace123', 'Using APIFY_API_UpperSecret999 and apify_mcp_OAuthSecret777')` leaves all three tokens unredacted in `_traceId` and `_useCase`.
- **AFTER PATCH**: Redacts `apify_api_*`, `apify_mcp_*`, and `Bearer *` case-insensitively across both `traceId` and `useCase`, and enforces `SAFE_TRACE_ID_REGEX` (`^[A-Za-z0-9._:-]{1,256}$`) on `traceId`.

5. Security Impact

Sensitive `apify_mcp_*` OAuth tokens, `Bearer` tokens, uppercase `APIFY_API_*` tokens in `_meta['com.apify/useCase']`, or any token accidentally passed in `_meta['com.apify/traceId']` / `mcpSessionId` are leaked unredacted into `GET /v2/store` URL query strings, HTTP access logs, and telemetry events.
