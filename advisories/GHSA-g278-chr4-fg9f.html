0x01 // Technical Specification & Remediation Patch

### Summary & Root-Cause Static Analysis

1. **Union Type Confusion via Out-of-Order `"tag"` Deserialization & Unrestricted `EXEC_TYPE_INTERNAL` Tag (`src/shared/gravity_value.c:966-1190`, `CWE-843`):**
   In `gravity_function_t` (`src/shared/gravity_value.h:285-308`), `f->tag` discriminates an anonymous `union` shared between `EXEC_TYPE_NATIVE` (`cpool`, `pvalue`, `pname`, `ninsts`, `bytecode`, `lineno`), `EXEC_TYPE_INTERNAL` (`gravity_c_internal internal` callback pointer at union offset `0`), and `EXEC_TYPE_SPECIAL` (`uint16_t index; void *special[2]` at union offsets `8` and `16`). Because `gravity_function_new()` initializes `f->tag = EXEC_TYPE_NATIVE` (`0`) and `gravity_function_deserialize()` processes JSON keys in arbitrary order, supplying `"pool"` (or `"bytecode"`, `"pvalues"`, `"pnames"`) prior to `"tag": 3` (`EXEC_TYPE_SPECIAL`) or `"tag": 1` (`EXEC_TYPE_INTERNAL`) aliases the initialized `cpool` struct fields (`cpool.n`, `cpool.m`, `cpool.p`) directly onto `f->special[0..1]` (`gravity_closure_t *`) or `f->internal` (`gravity_c_internal`).

2. **Heap-Based Buffer Over-Read & `f->ninsts` Overwrite via `"lineno"` Deserialization (`src/shared/gravity_value.c:1068-1070`, `CWE-125`):**
   The `GRAVITY_JSON_LABELLINENO` handler calls `gravity_bytecode_deserialize(..., &f->ninsts)` without checking `f->tag == EXEC_TYPE_NATIVE` and overwrites `f->ninsts` with the decoded length of the `"lineno"` buffer. When `"lineno"` is longer than `"bytecode"` (in either key order), subsequent serialization (`JSON.stringify()` -> `gravity_function_bytecode_serialize()`) or bytecode traversal reads past the end of the heap-allocated `f->bytecode` buffer.
