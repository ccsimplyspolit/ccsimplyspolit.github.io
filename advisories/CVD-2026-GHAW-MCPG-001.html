1. Summary

During a defensive static source audit of `https://github.com/github/gh-aw-mcpg` (`main` branch, commit `a5fcd9e3f37f`, pushed `2026-10-25T22:47:48Z`), I identified three container bind-mount policy bypasses in `internal/launcher/mount_policy.go` (introduced in `a5fcd9e3f37f`): 1. **Read-Only Sub-Root Bypass via Enclosing Parent Read-Write Mount (`CWE-284` / `CWE-732`, `internal/launcher/mount_policy.go:206-220`)**: `ValidateMount()` checks whether `source` is under the closest enclosing policy root (`isUnderRoot(source, root.Path)`), but when `decl.writable` is `true`, it never checks whether `source` encompasses a narrower read-only (`!subRoot.Writable`) policy root (e.g., policy allows `/workspace:rw` and restricts `/workspace/.git:ro` or `/workspace/secrets:ro`). Mounting `-v /workspace:/mnt:rw` matches `/workspace` (`Writable: true`) and grants the container full read-write access to the nested read-only `/workspace/.git` directory. 2. **Duplicate Root Deduplication Drops Read-Only Restriction (`CWE-732`, `internal/launcher/mount_policy.go:106-126`)**: `canonicalizeRoots()` deduplicates canonical paths using `if seen[path] { continue }`. If the same canonical path appears twice (e.g., via symlink alias or config composition) with `Writable: true` first and `Writable: false` second, the restrictive `Writable: false` entry is silently discarded. 3. **Dangling Symlink Traversal in `canonicalizePath()` (`CWE-59`, `internal/launcher/mount_policy.go:136-163`)**: When `filepath.EvalSymlinks(current)` fails with `os.IsNotExist(err)` (which occurs when `current` is a dangling symbolic link pointing outside all allowed mount roots), `canonicalizePath()` treats `current` as a plain non-existent directory entry and resolves its parent (`filepath.Dir(current)`), allowing a dangling symlink inside `/workspace` pointing to `/etc/cron.d/job` to pass `ValidateMount()` and cause the container runtime to create/bind the target host path.

5. Security Impact

An untrusted MCP server container configuration can bypass read-only sub-root protections (modifying `.git/hooks`, `.github/workflows`, or protected credentials subdirectories) or traverse outside allowed mount roots via a dangling symlink.
