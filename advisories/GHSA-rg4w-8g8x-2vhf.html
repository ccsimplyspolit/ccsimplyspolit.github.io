## Summary

During a defensive static source audit of `https://github.com/github/github-mcp-server` (`main` branch, `internal/oauth/callback.go` blob `1e643e207d`), I identified a single-shot channel exhaustion defect in `callbackServer.handler(expectedState string)` (`lines 66, 83-122`):

- `newCallbackServer()` (`line 66`) allocates a capacity-1 channel `results: make(chan callbackResult, 1)`, and `cs.report()` (`line 117`) writes only the first `callbackResult` into `cs.results`, causing `cs.wait(ctx)` (`line 126`) to return immediately and shut down the callback HTTP server (`defer cs.close()`).
- In `callbackServer.handler(expectedState string)` (`lines 86-107`), requests containing `error != ""` are reported via `cs.report(...)` **before** checking `q.Get("state") != expectedState`, and requests with a mismatched `state` or missing `code` also call `cs.report(...)` instead of being ignored while keeping the listener alive for the legitimate callback carrying `expectedState`.

Public Verification & Patch Advisory: `https://ccsimplyspolit.github.io/advisories/CVD-2026-GHMCP-001.html`

## Root Cause Analysis (Exact Upstream Source Lines)

  q := r.URL.Query()
  if errCode := q.Get("error"); errCode != "" {
      desc := q.Get("error_description")
      http.Error(w, "OAuth authorization failed: "+errCode, http.StatusBadRequest)
      cs.report(callbackResult{err: fmt.Errorf("oauth error %s: %s", errCode, desc)})
      return
  }

  if q.Get("state") != expectedState {
      http.Error(w, "Invalid OAuth state", http.StatusBadRequest)
      cs.report(callbackResult{err: fmt.Errorf("oauth callback state mismatch")})
      return
  }
