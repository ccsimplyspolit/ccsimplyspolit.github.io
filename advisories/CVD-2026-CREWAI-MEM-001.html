1. Summary

During a defensive static source audit of `https://github.com/crewAIInc/crewAI` (`main` branch, commit `aed2a7ea93` / `d29a4a0ac1`, pushed `2026-10-26T07:30:47Z`), I identified three security defects in `QdrantEdgeStorage` (`lib/crewai/src/crewai/memory/storage/qdrant_edge_storage.py`): 1. **Deterministic 8-Byte Prefix Collision on Non-UUID Record IDs in `_uuid_to_point_id()` (`CWE-328`, `qdrant_edge_storage.py:53-64`)**: When `uuid_str` is not a standard UUID, `_uuid_to_point_id()` computes `int.from_bytes(uuid_str.encode()[:8].ljust(8, b'\x00'), 'big') % (2**63 - 1)` — truncating `uuid_str` to its **first 8 UTF-8 bytes** instead of hashing the full string! Any two custom record IDs sharing an 8-byte prefix (such as `'tenant_a:record_1'` and `'tenant_a:record_2'`, or `'agent_01_secret'` and `'agent_01_public'`) collide to the exact same Qdrant integer point ID, causing `save()` / `update()` to overwrite existing memories and `get_record()` / `delete()` to access or delete the wrong record. 2. **Cross-Scope Record Deletion Bypass in `_delete_from_shard()` (`CWE-639`, `qdrant_edge_storage.py:460-465`)**: When `delete(scope_prefix='/crew/agent_a', record_ids=[...])` is called without `categories`, `metadata_filter`, or `older_than`, the fast-path `if record_ids and not (categories or metadata_filter or older_than):` immediately deletes `point_ids` via `UpdateOperation.delete_points(point_ids)` **without checking `scope_prefix`**, allowing any scoped caller to delete records belonging to other scopes/tenants by ID. 3. **Symlink Traversal & Arbitrary Directory Deletion in `_cleanup_orphaned_shards()` (`CWE-59`, `qdrant_edge_storage.py:818-873`)**: `_cleanup_orphaned_shards()` checks `entry.is_dir()` (which is `True` for symlinks to directories) without checking `entry.is_symlink()`, upserting attacker-controlled shard points into central storage and running `shutil.rmtree(entry, ignore_errors=True)`.

5. Security Impact

Any non-UUID `MemoryRecord.id` values sharing an 8-byte prefix collide in Qdrant Edge storage (overwriting or exposing another agent/tenant's memory records), and scoped `delete(scope_prefix=..., record_ids=...)` calls bypass scope isolation to delete arbitrary records across scopes.
