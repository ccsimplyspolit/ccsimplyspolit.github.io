CVD-2026-MONGODB-MCP-001: Prompt-Injection Defense Bypass via Unconstrained disableUntrustedDataWarning Override and Non-Positive Resource Limit Overrides in @mongodb-js/mongodb-mcp-server

High (CVSS 8.1) CWE-863 / CWE-20 GitHub CNA PVR + HackerOne: mongodb
Target Repository: mongodb-js/mongodb-mcp-server (commit 1b117c7c3cfd, 2026-10-23T15:22:28Z)
Affected Component: packages/cli/src/config/userConfig.ts (lines 128-134), packages/cli/src/config/configUtils.ts (lines 120-133), packages/cli/src/config/configOverrides.ts (lines 66-72)
Researcher: Serhii Shunko (@sshunko / @ccsimplyspolit, ORCID 0009-0002-4183-0361)

1. Summary

During a defensive static source audit of `https://github.com/mongodb-js/mongodb-mcp-server` (`main` branch, commit `1b117c7c3cfd`, pushed `2026-10-23T15:22:28Z`), I identified three security defects in the HTTP request/session configuration override subsystem: 1. **Remote Disabling of Prompt-Injection Delimiters via `disableUntrustedDataWarning` Override (`CWE-863`, `packages/cli/src/config/userConfig.ts:128-134`)**: Unlike `readOnly` (which uses `oneWayOverride(true)`) and `indexCheck` (which uses `oneWayOverride(true)`), `disableUntrustedDataWarning` is registered with `{ overrideBehavior: "override" }`. Consequently, when HTTP header/query config overrides are enabled, an untrusted client request can pass `disableUntrustedDataWarning=true` to strip the `<untrusted-user-data-...>` delimiters and prompt-injection warning wrapper from all MongoDB query outputs. 2. **Non-Positive (`<= 0`) Resource Limit Bypass in `onlyLowerThanBaseValueOverride()` (`CWE-20`, `packages/cli/src/config/configUtils.ts:120-133`)**: `onlyLowerThanBaseValueOverride()` only checks `if (newValue >= oldValue)` without rejecting `newValue <= 0` (`0`, `-1`, or `NaN`), allowing callers to set `maxBytesPerQuery`, `maxDocumentsPerQuery`, or timeout parameters to `0` or negative integers. 3. **Stale `baseConfig[key]` Comparison in `applyConfigOverrides()` (`CWE-863`, `packages/cli/src/config/configOverrides.ts:66-72`)**: `applyConfigOverrides()` reads `const baseValue = baseConfig[key]` rather than `result[key]`, so subsequent keys or layered overrides compare against the initial static base config rather than the already-narrowed `result`.

2. Root Cause Analysis

- **`packages/cli/src/config/userConfig.ts:128-134`**:
```typescript
    disableUntrustedDataWarning: z
        .preprocess(parseBoolean, z.boolean())
        .default(false)
        .describe(
            "When set to true, tool responses include potentially untrusted data (such as documents or query results) as-is, without wrapping it in delimiters and a prompt-injection warning."
        )
        .register(configRegistry, { overrideBehavior: "override" }),
```
- **`packages/cli/src/config/configUtils.ts:125-131`**:
```typescript
        if (typeof newValue !== "number") {
            throw new Error(`Unsupported type for new value for override: ${typeof newValue}`);
        }
        if (newValue >= oldValue) {
            throw new Error(`Can only set to a value lower than the base value`);
        }
        return newValue;
```

3. Steps to Reproduce (BEFORE PATCH vs. AFTER PATCH)

Run the standalone verification test suite in `verify_batch7_fresh_ai_cna.py` (`test_03_mongodb_mcp_config_overrides`):
```bash
uv run verify_batch7_fresh_ai_cna.py
```
- **BEFORE PATCH**: `mongo_lower_before(600000, 0)` returns `'ACCEPTED:0'`, and `disableUntrustedDataWarning` allows overriding `false -> true`.
- **AFTER PATCH**: Enforces `oneWayOverride(false)` on `disableUntrustedDataWarning`, rejects `newValue <= 0` in `onlyLowerThanBaseValueOverride()`, and compares against `result[key]`.

5. Security Impact

Remote HTTP MCP callers or injected session parameters can disable MongoDB MCP's untrusted-data prompt-injection wrapper (`disableUntrustedDataWarning=true`) and pass `0` or negative values to numeric resource guards.
