0x01 // Technical Specification & Remediation Patch

### Summary & Root-Cause Static Analysis

1. **Stack-Based Buffer Overflow in `GPMF_ScaledData()` via Unbounded `ORIN`/`ORIO` Matrix Generation & `MACRO_APPLY_CALIBRATION` (`GPMF_parser.c:1503, 1739-1772, 1859-1873`, `CWE-121` / `CWE-787`):**
   In `GPMF_ScaledData()`, the calibration matrix buffer is allocated on the stack with a fixed size of 256 bytes (`uint32_t mtrx_buffer[64]`). For any non-complex sample tag (such as `ACCL` with `GPMF_TYPE_SIGNED_BYTE`, `inputtypesize = 1`), `elements = sample_size / inputtypesize` can be up to `255`. When the stream contains matching `ORIN` and `ORIO` orientation tags (`orio_len == orin_len && orin_len > 1 && orio_len == elements`), `GPMF_ScaledData()` populates an `elements x elements` matrix of `outputType` into `mtrx_buffer` without verifying that `elements * elements * output_sample_size <= sizeof(mtrx_buffer)`, and `MACRO_APPLY_CALIBRATION` writes `elements` entries into a fixed 8-element stack array `outputcast tmpbuf[8]`.

2. **Off-by-One Out-of-Bounds Write on `ms->nest_size[GPMF_NEST_LIMIT]` in `GPMF_Validate()` & `GPMF_Next()` (`GPMF_parser.c:122-128, 304-308`, `CWE-193` / `CWE-787`):**
   Both functions increment `ms->nest_level++` and check `if (ms->nest_level > GPMF_NEST_LIMIT)` instead of `>= GPMF_NEST_LIMIT` (`16`), indexing `ms->nest_size[16]` one element past the 16-element array.

3. **Unsigned Integer Underflow in `sample_offset` Calculation & Dead Bounds Check in `GPMF_Decompress()` / `GPMF_ExpandComplexTYPE()` (`GPMF_parser.c:1072-1103, 1193, 1549-1593, 1926-1933`, `CWE-191` / `CWE-125`):**
   `remaining_sample_size -= sample_offset * sample_size` executes before checking `(uint64_t)sample_offset * sample_size <= remaining_sample_size`; `GPMF_Decompress()` guards `localbuf_size < uncompressed_size` behind the dead condition `sizeoftype == 0`; and `GPMF_ExpandComplexTYPE()` scans digits in `src[i + j]` without checking `(i + j) < srcsize`.
