0x01 // Technical Specification & Remediation Patch

### Summary & Root-Cause Static Analysis

1. **Incomplete Fix for `GHSA-pcc4-rvhr-2pr8` in `graphify/extractors/fortran.py` (`_strip_include_directives`, `lines 14-70`, `CWE-184` / `CWE-200`):**
   `_strip_include_directives(source: bytes)` splits raw bytes on `b"\n"` and blanks lines matching `_INCLUDE_DIRECTIVE_RE = re.compile(rb"^[ \t]*#[ \t]*include\b")` before piping the buffer to `cpp -w -P -nostdinc -I /dev/null`. However, ISO C / GNU / Clang `cpp` performs Translation Phase 2 (backslash-newline splicing `\\\n`) and Translation Phase 3 (`/* ... */` block-comment replacement, `\f`/`\v` whitespace, and standalone `\r` line terminators) *prior* to directive recognition, and supports additional file-inclusion directives (`#include_next`, `#import`, and C23 `#embed`) that do not match `include\b`.

2. **IPv6 Transition-Address Unwrapping & `yt_dlp` Redirect SSRF Bypass in `graphify/security.py` & `graphify/transcribe.py` (`lines 83-105` & `65-92`, `CWE-918`):**
   `_ip_is_blocked()` only unwraps RFC 6052 `64:ff9b::/96` before checking `_CGN_NETWORK` (`100.64.0.0/10`) and private ranges, missing IPv4-mapped IPv6 (`::ffff:0:0/96`), 6to4 (`2002::/16`), Teredo (`2001::/32`), and RFC 8215 local-use NAT64 (`64:ff9b:1::/48`). Furthermore, `download_audio(url)` in `graphify/transcribe.py` validates only the initial URL string before delegating media manifest and redirect fetching to `yt_dlp.YoutubeDL` without re-validating resolved stream targets.
