0x01 // Technical Specification & Remediation Patch

### Summary
In `crates/openhuman-core/src/security/policy/command_analysis.rs`, `command_checks.rs`, `command_vocabulary.rs`, and `util/url.rs` (`<= v0.64.15`), `OpenHumanSecurityGate` relies on `CommandAnalysis::from_shell_analysis` and `SecurityPolicy::check_gated_command_analysis` to enforce the unconditional protected-path floor (`SENSITIVE_COMPONENTS` such as `.ssh`/`.aws`, `SENSITIVE_FILES`, and `ALWAYS_FORBIDDEN_PREFIXES` such as `/etc`) and to classify `Read`-only shell commands (`GateDecision::Allow` without human approval across all autonomy tiers, including `ReadOnly` and `Supervised`). Three flaws allow shell commands to bypass these guards:

### Root Cause Analysis
1. **Intra-Word Quote Splitting in `CommandAnalysis::from_shell_analysis` Breaks `check_protected_path_words` (`crates/openhuman-core/src/security/policy/command_analysis.rs:83-94`)**:
   - While `normalized_command_name()` (`command_vocabulary.rs:320-338`) uses `shell_unquote()` to strip syntactic quotes inside a shell word the way the shell does (`c''url` -> `curl`), `CommandAnalysis::from_shell_analysis` (`command_analysis.rs:84-93`) populates `analysis.literal_words` by splitting `source` directly on `'` and `"` characters:
     ```rust
     source.split(|c: char| {
         c.is_whitespace()
             || matches!(c, '\'' | '"' | '(' | ')' | '[' | ']' | ',' | ';' | '=' | '@')
     })
     ```
   - Consequently, a shell-quoted protected path such as `/et"c"/passwd` or `~/.s's'h/id_rsa` is split into separate fragments (`["/et", "c", "/passwd"]` or `["~/.s", "s", "h/id_rsa"]`) instead of being unquoted into `/etc/passwd` or `~/.ssh/id_rsa`.
   - None of the split fragments match `is_always_forbidden()`, and when paired with a `READ_ONLY_BASES` command (`cat`, `head`, `tail`, `grep`, `rg`), `check_gated_command_analysis` returns `Ok(CommandClass::Read)`, allowing unprompted reads of protected credential stores even in `AutonomyLevel::ReadOnly` and `AutonomyLevel::Supervised`.
2. **Unconditional `word.contains("://")` Skip in `check_protected_path_words` Misses `file://` URLs (`crates/openhuman-core/src/security/policy/command_checks.rs:438`)**:
   - `check_protected_path_words()` skips any token containing `"://"` (`if word.is_empty() || word.contains("://") { continue; }`), which exempts `file:///etc/passwd` and `file:///Users/<user>/.ssh/id_rsa` from the protected-path floor.
3. **`git diff` / `git log` / `git show` with `--output=<path>` Classified as `CommandClass::Read` (`crates/openhuman-core/src/security/policy/command_vocabulary.rs:573-588`)**:
   - `classify_host_command` classifies `git` subcommands solely by checking whether `args.first()` is in `GIT_READ_VERBS` (`diff`, `log`, `show`, `status`, etc.), without checking for `--output=<file>` or `-O` flags (unlike `tree -o` and `rg --pre` on lines 598–599). Because `git diff --output=<file>` and `git log --output=<file>` write directly to `<file>`, classifying them as `CommandClass::Read` permits arbitrary file creation/overwrite in `AutonomyLevel::ReadOnly` and `AutonomyLevel::Supervised` without human approval.
4. **`host_is_local` Omits IPv4-Mapped IPv6 (`[::ffff:127.0.0.1]`) Despite Explicit Documentation Claim (`crates/openhuman-core/src/util/url.rs:105-122`)**:
   - The doc comment on `host_is_local()` states that typed-host matching ensures `::ffff:127.0.0.1` classifies as local, but the `Some(url::Host::Ipv6(addr))` arm only checks `addr.is_loopback() || addr.is_unspecified()` (which returns `false` for `::ffff:127.0.0.1` in Rust's `std::net::Ipv6Addr`) without checking `addr.to_ipv4_mapped()`.

### Impact
- Bypass of the unconditional protected-path floor (`check_protected_path_words`) for credential stores (`.ssh`, `.aws`, `.gnupg`, `/etc`) and bypass of `AutonomyLevel::ReadOnly` / `AutonomyLevel::Supervised` write restrictions via `git diff/log/show --output=<file>`.

### Recommended Remediation
1. In `CommandAnalysis::from_shell_analysis`, apply `shell_unquote()` to each shell word (and sub-tokens split on `=`, `@`, `,`) rather than splitting on `'` and `"`.
2. In `check_protected_path_words`, strip `file://` prefixes instead of skipping `file://` URLs.
3. In `classify_host_command`, treat `git` with `--output` / `--output=*` / `-c` / `--exec-path` as `CommandClass::Write`.
4. In `host_is_local`, delegate `addr.to_ipv4_mapped()` to the IPv4 locality check:
