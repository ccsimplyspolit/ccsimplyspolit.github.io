0x01 // Technical Specification & Remediation Patch

### Summary & Root-Cause Static Analysis

1. **Remote Pre-Auth Infinite Loop, Heap Exhaustion & OOB Under-Read in `Calendar_Write_Property()` (`src/bacnet/basic/object/calendar.c:695-716`, `CWE-835` / `CWE-400` / `CWE-125`):**
   `bacnet_calendar_entry_decode()` returns `BACNET_STATUS_ERROR` (`-1`) when a context-2 `BACNET_CALENDAR_WEEK_N_DAY` entry has `octet_string.length != 3`, whereas `Calendar_Write_Property()` only checks `if (len == BACNET_STATUS_REJECT)` (`-2`). Consequently, `iOffset += len` decrements `iOffset` by `1` on `BACNET_STATUS_ERROR` (`-1`) and still calls `Calendar_Date_List_Add()` (`calloc`), causing either an infinite loop with unbounded heap allocation or an out-of-bounds buffer under-read at `&wp_data->application_data[-1]`.

2. **Out-of-Bounds Read via Unsubtracted `application_data_len` in `Notification_Class_Write_Property()` (`src/bacnet/basic/object/nc.c:508-531, 578-597`, `CWE-125`):**
   Both the `PROP_PRIORITY` (`BACNET_ARRAY_ALL`) loop and the `PROP_RECIPIENT_LIST` loop advance `&wp_data->application_data[iOffset]` while passing the full unsubtracted `wp_data->application_data_len` instead of `wp_data->application_data_len - iOffset`, and fail to reject negative decode returns (`len <= 0`).

3. **Discarded `BACNET_STATUS_ERROR` in `bacaction.c` & Off-by-One / Underflow in `bvlc-sc.c` (`src/bacnet/bacaction.c:225-245`, `src/bacnet/datalink/bsc/bvlc-sc.c:810, 2370-2388`, `CWE-787`):**
   `bacnet_action_property_value_decode()` adds `len = -1` to `apdu_len` without checking `len < 0`; `bvlc_sc_encode_result()` checks `pdu_len < offs + 4` before writing 5 bytes; and `bvlc_sc_remove_orig_and_dest()` executes `memmove(&pdu[offs - 4], pdu, 4)` without verifying `offs <= pdu_len`.
