CVD-2026-FASTMCP-001: Inbound Authorization Header Leakage When Transport Uses self.auth (client/transports/http.py) & Connection Hop-by-Hop Header Bypass in get_http_headers (server/dependencies.py)

High (CVSS 7.7) CWE-200 / CWE-444 GitHub CNA PVR + HackerOne: github
Target Repository: jlowin/fastmcp (commit 6d665f0f8d, 2026-10-24T05:19:38Z)
Affected Component: fastmcp_slim/fastmcp/client/dependencies.py (lines 6-20), client/transports/http.py (lines 168-172), & server/dependencies.py (lines 620-662)
Researcher: Serhii Shunko (@sshunko / @ccsimplyspolit, ORCID 0009-0002-4183-0361)

1. Summary

During a defensive static source audit of `https://github.com/jlowin/fastmcp` (`main` branch, commit `6d665f0f8d` / `12aefc84f6`, pushed `2026-10-24T05:19:38Z`), I identified an incomplete fix in commit `12aefc84f6` (*'Fix duplicate header errors when proxying over HTTP (#3833)'*): 1. **Inbound Caller `authorization` Header Forwarded Despite Configured Transport `self.auth` (`CWE-200` / `CWE-444`, `client/transports/http.py:168-172` & `client/dependencies.py:6-20`)**: `_merge_forwardable_http_headers(self.headers)` only checks whether keys exist in `self.headers`. When a `StreamableHttpTransport` or `SSETransport` is configured with `auth=BearerAuth(...)` or `auth='oauth'` (`self.auth is not None`) rather than a static `'Authorization'` entry in `self.headers`, `self.headers` does not contain `'authorization'`. Consequently, `_merge_forwardable_http_headers(self.headers)` copies the inbound caller's `authorization` header into the outbound request headers, colliding with or leaking the caller's bearer token to the downstream MCP server. 2. **RFC 9110 §7.6.1 `Connection`-Nominated Hop-by-Hop Header Bypass & Multi-Value Header Overwrite in `get_http_headers()` (`CWE-444`, `server/dependencies.py:620-662`)**: `get_http_headers()` fails to strip headers dynamically nominated inside the inbound `Connection` header (e.g., `Connection: x-forwarded-secret, authorization`) and overwrites multi-valued headers (`result[lower_name] = str(value)`) instead of comma-joining them per RFC 9110 §5.3.

2. Root Cause Analysis

- **`fastmcp_slim/fastmcp/client/dependencies.py:6-20`**:
```python
def _merge_forwardable_http_headers(headers: dict[str, str]) -> dict[str, str]:
    forwarded_headers = {
        k: v
        for k, v in get_http_headers().items()
        if k not in {"mcp-session-id", "mcp-protocol-version"}
    }
    existing_lower = {k.lower() for k in headers}
    merged = dict(headers)
    for k, v in forwarded_headers.items():
        if k.lower() not in existing_lower:
            merged[k] = v
    return merged
```
- **`fastmcp_slim/fastmcp/client/transports/http.py:168-172`**:
```python
    async def connect_session(
        self, **session_kwargs: Unpack[ SessionKwargs]
    ) -> AsyncIterator[ClientSession]:
        headers = _merge_forwardable_http_headers(self.headers)
        client = self._create_http_client(headers=headers)
```

- **BEFORE PATCH**: When `has_transport_auth=True` (`self.auth = BearerAuth(...)`) and `self.headers = {'X-Custom': '1'}`, `merge_before` copies the inbound caller's `'authorization': 'Bearer caller-secret'` into the downstream request.
- **AFTER PATCH**: Passes `has_auth=self.auth is not None` to `_merge_forwardable_http_headers()`, suppressing inbound `authorization` forwarding whenever transport-level `auth` is configured, and strips `Connection`-nominated headers in `get_http_headers()`.

5. Security Impact

FastMCP proxy servers that authenticate to downstream MCP backends via `auth=BearerAuth(...)` or `auth='oauth'` inadvertently forward the upstream caller's `Authorization` header (or cause duplicate `Authorization` headers in `httpx.Auth.auth_flow`), leaking upstream credentials across trust boundaries.
