CVD-2026-NETLIFY-MCP-001: Subdomain Origin Confusion & Bearer Token Leakage in Edge Proxy (proxy.ts) and Teredo IPv6 Bypass in callback-guard.ts

High (CVSS 8.6) CWE-918 / CWE-285 / CWE-200 GitHub CNA PVR + HackerOne: netlify
Target Repository: netlify/netlify-mcp (commit 080752a77c84, 2026-10-23T21:25:38Z)
Affected Component: netlify/edge-functions/proxy.ts (lines 56-101) & netlify/functions/mcp-server/events/callback-guard.ts (lines 61-71)
Researcher: Serhii Shunko (@sshunko / @ccsimplyspolit, ORCID 0009-0002-4183-0361)

1. Summary

During a defensive static source audit of `https://github.com/netlify/netlify-mcp` (`main` branch, commit `080752a77c84`, pushed `2026-10-23T21:25:38Z`), I identified three security defects in the Netlify MCP Edge Proxy and event callback SSRF guard: 1. **Subdomain Origin Confusion & Bearer Token Exfiltration (`CWE-918` / `CWE-200`, `netlify/edge-functions/proxy.ts:56-68, 92`)**: `handleProxy()` constructs `const url = new URL(requestedPath as string, 'https://api.netlify.com')` from `req.url.split(token)[1]` and checks `if (!url.origin.endsWith('.netlify.com'))`. Because WHATWG `new URL('//app-preview.netlify.com/api/v1/user', 'https://api.netlify.com')` resolves the origin to `https://app-preview.netlify.com` (which satisfies `.endsWith('.netlify.com')`), a protocol-relative `requestedPath` causes the Edge proxy to attach `Authorization: Bearer ${decryptedToken.accessToken}` and forward the decrypted Netlify personal/OAuth access token to any customer-deployed `.netlify.com` subdomain. 2. **HTTP Method Mismatch & Optional `apisAllowed` Bypass (`CWE-285`, `netlify/edge-functions/proxy.ts:72-97`)**: `apisAllowed` checks `method === req.method`, whereas the outbound `Request` uses `method: decryptedToken.apiMethod as string | undefined || req.method`. Furthermore, if `decryptedToken.apisAllowed` is omitted or non-array, the `if (Array.isArray(decryptedToken.apisAllowed))` guard is skipped completely. 3. **Incomplete IPv6 Special/Tunnel Range Filtering in `isPrivateIPv6()` (`CWE-918`, `netlify/functions/mcp-server/events/callback-guard.ts:61-71`)**: `isPrivateIPv6()` treats all `2000::/3` (`0x2000..0x3fff`) addresses except `2002::/16` (6to4) as public, failing to block `2001:0000::/32` (RFC 4380 Teredo IPv4 tunneling), `2001:2::/48` (RFC 5180 benchmarking), and `2001:db8::/32` (RFC 3849 documentation).

  const first = ip.toLowerCase().split('%')[0].split(':')[0];

5. Security Impact

A caller holding a scoped proxy JWE token can redirect the Edge proxy to an arbitrary `.netlify.com` site via a `//<subdomain>.netlify.com/...` path and capture the decrypted `Authorization: Bearer <accessToken>` header, escalating from a single-endpoint proxy token to full Netlify account access.
