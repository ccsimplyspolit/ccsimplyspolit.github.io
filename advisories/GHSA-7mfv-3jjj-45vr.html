0x01 // Technical Specification & Remediation Patch

### Summary
In `colbymchenry/codegraph` (`<= 1.6.2`), `src/upgrade/index.ts` resolves or accepts a target version string via `normalizeVersion()` without validating that it conforms to a strict semantic version syntax (`parseSemver()`). This unvalidated `version` string is subsequently interpolated directly into:
1. A double-quoted PowerShell command string (`Write-Host "Installed CodeGraph ${version} to $dest"`) inside `buildWindowsUpgradeScript()` (`src/upgrade/index.ts:807`), which is executed via `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`.
2. An unquoted command-line string (`['npm', ...npmArgs].join(' ')`) passed to `cmd.exe /d /s /c` inside `npmInvocation()` (`src/upgrade/index.ts:858-860`) on Windows.

### Affected Code

#### 1. Missing Semver Validation in `normalizeVersion()` and `parseLatestTagFromLocation()` (`src/upgrade/index.ts:273-292`)
```ts
export function normalizeVersion(v: string): string {
  const t = v.trim();
  return t.startsWith('v') ? t : `v${t}`;
}

export function parseLatestTagFromLocation(location: string | undefined): string | null {
  if (!location) return null;
  const m = /\/releases\/tag\/([^/?#]+)/.exec(location);
  return m ? decodeURIComponent(m[1]!) : null;
}
```
In `parseSemver(version)` (`src/upgrade/index.ts:236-245`), the regular expression `/^v?(\d+)\.(\d+)\.(\d+)(?:-([0-9A-Za-z.-]+))?/` is missing a trailing `$` end-of-string anchor, allowing any string with a valid semver prefix followed by arbitrary shell/PowerShell metacharacters (e.g., `v9.9.9$(...)` or `v9.9.9 & ...`) to pass `parseSemver()` and `compareVersions()`. Furthermore, `normalizeVersion()` (`src/upgrade/index.ts:273-276`) does not validate `v` against an anchored semver regex.

#### 2. Unescaped Interpolation into Double-Quoted PowerShell String (`src/upgrade/index.ts:781-815`)
```ts
export function buildWindowsUpgradeScript(
  bundleRoot: string,
  version: string,
  arch = resolveWindowsArch()
): string {
  const asset = `codegraph-${version}-${arch}.zip`;
  const url = `https://github.com/${REPO}/releases/download/${version}/${asset}`;
  const psDest = bundleRoot.replace(/'/g, "''");
  const psUrl = url.replace(/'/g, "''");
  const psAsset = asset.replace(/'/g, "''");
  return [
    // ...
    `Write-Host "Installed CodeGraph ${version} to $dest"`,
    // ...
  ].join('\r\n');
}
```
While `psDest`, `psUrl`, and `psAsset` escape single quotes for single-quoted PowerShell literals, line 807 interpolates `${version}` directly inside a double-quoted PowerShell string (`"Installed CodeGraph ${version} to $dest"`), where PowerShell evaluates `$(...)` subexpressions, `$variable` expansions, backtick escapes, and double quotes.

#### 3. Unquoted `cmd.exe /d /s /c` String Concatenation in `npmInvocation()` (`src/upgrade/index.ts:858-863`)
```ts
export function npmInvocation(npmArgs: string[], platform: NodeJS.Platform = process.platform): NpmInvocation {
  if (platform === 'win32') {
    return {
      command: process.env.ComSpec || 'cmd.exe',
      args: ['/d', '/s', '/c', ['npm', ...npmArgs].join(' ')],
    };
  }
```
When `runNpmInstall(version)` constructs `spec = '@colbymchenry/codegraph@' + stripV(version)`, `['npm', ...npmArgs].join(' ')` concatenates the version specifier into a raw `cmd.exe` command string without validating `version` or escaping `cmd.exe` metacharacters (`&`, `|`, `;`, `^`, `"`).

### Impact
If `runUpgrade({ version })` or `resolveLatestVersion()` receives an untrusted version string (for example via an automated wrapper, MCP/agent configuration, or a spoofed/redirected `Location` header decoded by `decodeURIComponent()`), arbitrary PowerShell subexpressions or `cmd.exe` commands can be injected during the upgrade workflow on Windows.

### Recommended Fix
1. Enforce strict semantic version validation (`parseSemver(v)`) inside `normalizeVersion(v)` (or at the entry of `runUpgrade()`, `buildWindowsUpgradeScript()`, and `runNpmInstall()`), throwing an error if `parseSemver(v)` fails.
2. In `buildWindowsUpgradeScript()`, avoid interpolating `${version}` into a double-quoted PowerShell string (use single-quoted strings or validate `version` against `/^v\d+\.\d+\.\d+(?:-[0-9A-Za-z.-]+)?$/`).

```ts
export function normalizeVersion(v: string): string {
  const t = v.trim();
  parseSemver(t); // Validate strict semver format before use in URLs or shell scripts
  return t.startsWith('v') ? t : `v${t}`;
}
```
