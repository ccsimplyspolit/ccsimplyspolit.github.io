1. Summary

During a defensive static source audit of `https://github.com/github/gh-aw-firewall` (`main` branch, commit `b6cfc3c149`, pushed `2026-10-26T00:32:25Z`), I identified two root-level symlink-traversal defects in the Agentic Workflows Firewall host helper: 1. **Root `fs.chownSync` Without `assertRealDirectory` in `prepareChrootHomeMounts()` (`CWE-59`, `src/chroot-home-setup.ts:58-63, 77-81`)**: `prepareChrootHomeMounts()` creates `emptyHomeDir = path.join(workDir, 'empty-home')` with `fs.mkdirSync(..., { recursive: true })` and immediately calls `fs.chownSync(emptyHomeDir, containerUid, containerGid)` as root without calling `assertRealDirectory(emptyHomeDir)`. Similarly, in the `.gemini` setup loop, `assertRealDirectory(toolPathSource)` is only called inside `if (!fs.existsSync(toolPathSource))`, whereas a pre-existing `toolPathSource` symlink is passed directly to `fs.chownSync(toolPathSource, containerUid, containerGid)` (which dereferences symlinks on Linux), changing ownership of an arbitrary host file/directory to the unprivileged container UID/GID. 2. **Unvalidated `docker cp` Destination in `preserveIptablesAudit()` (`CWE-59`, `src/artifact-preservation.ts:70-105`)**: Whereas `preserveWorkDirArtifacts()` validates `isRealDirectory(targetArtifactDir)` and checks `fs.lstatSync(destPath).isSymbolicLink()` before copying, `preserveIptablesAudit()` runs `execa('docker', ['cp', 'awf-squid:/var/log/squid/iptables-audit.txt', destination])` before checking `isRealDirectory(targetAuditDir)` or verifying that `destination` is not a pre-created symlink.

3. Steps to Reproduce (BEFORE PATCH vs. AFTER PATCH)

Run the standalone verification test suite in `verify_batch8_fresh_ai_cna.py` (`test_01_github_gh_aw_firewall_symlink_and_audit`):
```bash
uv run verify_batch8_fresh_ai_cna.py
```
- **BEFORE PATCH**: A pre-existing symlink at `.gemini` (`toolPathSource`) or `empty-home` skips `assertRealDirectory()` and reaches `fs.chownSync()` as root; `preserveIptablesAudit()` executes `docker cp` before verifying `isRealDirectory(targetAuditDir)` or checking `destination` for symlinks.
- **AFTER PATCH**: Calls `assertRealDirectory(emptyHomeDir)` and `assertRealDirectory(toolPathSource)` unconditionally before `fs.chownSync()`, and validates `isRealDirectory(targetAuditDir)` and `!fs.lstatSync(destination).isSymbolicLink()` before `docker cp`.

5. Security Impact

When `gh-aw-firewall` runs with root privileges on the GitHub Actions host runner, a pre-existing symlink in the workspace or home directory allows changing ownership of arbitrary host files to the unprivileged container UID/GID or overwriting host files via `docker cp`.
