CVD-2026-HF-MCP-001: Authenticated Hugging Face API Path Traversal in parseGradioSpaceIds (gradio-utils.ts) & Permissive HTTP Schema Fetch in proxy-tools-config.ts

Target Repository: huggingface/hf-mcp-server (commit 299718b1ad, 2026-10-24T10:20:50Z)
Affected Component: packages/app/src/server/utils/gradio-utils.ts (lines 122-135), gradio-discovery.ts (line 126), & proxy-tools-config.ts (lines 46, 146-149)
Researcher: Serhii Shunko (@sshunko / @ccsimplyspolit, ORCID 0009-0002-4183-0361)

1. Summary

During a defensive static source audit of `https://github.com/huggingface/hf-mcp-server` (`main` branch, commit `299718b1ad`, pushed `2026-10-24T10:20:50Z`), I identified two security defects in the Gradio Space discovery and Proxy Tools schema loader: 1. **Authenticated Hugging Face API Path Traversal via Backslash / Dot-Segment in `parseGradioSpaceIds()` (`CWE-22` / `CWE-918`, `gradio-utils.ts:122-135` & `gradio-discovery.ts:126`)**: `parseGradioSpaceIds()` validates each comma-separated entry from `X-HF-Gradio-Spaces` / query parameters only by checking `slashCount === 1 && slashIndex > 0 && slashIndex < entry.length - 1`. It does not reject backslashes (`\`), `..` segments, `?`, `#`, or `%`. When `gradio-discovery.ts` calls `fetch(\`https://huggingface.co/api/spaces/\${spaceName}\`, { headers: { Authorization: \`Bearer \${hfToken}\` } })`, WHATWG `fetch()` normalizes `\` to `/` and resolves `..` path segments (e.g., `..\whoami-v2/x` resolves to `https://huggingface.co/api/whoami-v2/x`), sending the user's `Authorization: Bearer ${hfToken}` to arbitrary `/api/...` endpoints on `huggingface.co`. 2. **Plaintext HTTP Allowance & Missing `fetchWithProfile` Guard in `proxy-tools-config.ts` (`CWE-918` / `CWE-319`, `proxy-tools-config.ts:46, 146-149`)**: `csvRowSchema` validates upstream URLs with `httpOrHttpsPermissive()` (allowing `http://` URLs), and `fetchProxyToolSchemas()` calls `new StreamableHTTPClientTransport(new URL(config.url), { requestInit: headers ? { headers } : undefined })` with `Authorization: Bearer ${hfToken}` without passing `fetch: fetchWithProfile('external_https_Closure')`.

2. Root Cause Analysis

- **`packages/app/src/server/utils/gradio-utils.ts:122-135`**:
```typescript
export function parseGradioSpaceIds(rawValue: string | undefined): string[] {
	if (!rawValue) return [];
	const seen = new Set<string>();
	for (const part of rawValue.split(',')) {
		const entry = part.trim();
		const slashCount = (entry.match(/\//g) || []).length;
		const slashIndex = entry.indexOf('/');
		if (slashCount === 1 && slashIndex > 0 && slashIndex < entry.length - 1 && !seen.has(entry)) {
			seen.add(entry);
		}
	}
	return [...seen];
}
```
- **`packages/app/src/server/utils/gradio-discovery.ts:126`**:
```typescript

		headers: {

		},

```

```bash

```
- **BEFORE PATCH**: `parse_space_before('..\\whoami-v2/x')` passes the single-slash check and resolves `https://huggingface.co/api/spaces/..\whoami-v2/x` to `/api/whoami-v2/x`.
- **AFTER PATCH**: Enforces `^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$`, rejects `\`, `?`, `#`, `%`, `.` and `..`, URL-encodes each path segment in `gradio-discovery.ts`, and enforces `httpsOnly()` + `fetchWithProfile('external_https_Closure')` in `proxy-tools-config.ts`.

5. Security Impact

An attacker supplying a crafted Gradio Space ID via query parameters or headers can traverse out of `/api/spaces/` into arbitrary authenticated `huggingface.co/api/...` endpoints using the victim's `hfToken`, and `proxy-tools-config.ts` can transmit `Authorization: Bearer ${hfToken}` over plaintext HTTP without the `external_https_Closure` SSRF profile.
