0x01 // Technical Specification & Remediation Patch

### Summary & Root-Cause Static Analysis

1. **Out-of-Bounds Array Read in `needsAsyncCallback()` & `queueAsyncCallback()` (`src/ControlStream.c:147-202, 1035-1102`, `CWE-125`):**
   When `IDX_DS_ADAPTIVE_TRIGGERS` (`#define IDX_DS_ADAPTIVE_TRIGGERS 12`) was added to `packetTypesGen7Enc[]` (13 elements, indices `0..12`), the corresponding sentinel entry (`-1`) was omitted from `packetTypesGen3[]`, `packetTypesGen4[]`, `packetTypesGen5[]`, and `packetTypesGen7[]` (12 elements each, indices `0..11`). However, `needsAsyncCallback()` and `queueAsyncCallback()` unconditionally index `packetTypes[IDX_DS_ADAPTIVE_TRIGGERS]` (`packetTypes[12]`), reading 2 bytes past the end of the active 12-element table into adjacent `.rodata`.

2. **Unchecked `BbGet*` Return Values & Uninitialized Heap/Stack Memory Exposure (`src/ControlStream.c:1051-1107, 1279-1372`, `CWE-908`):**
   `queueAsyncCallback()` allocates `queuedCb` via `malloc(sizeof(*queuedCb))` without zero-initialization and does not check the boolean return values of `BbGet8()`, `BbGet16()`, or `BbGetBytes()`. Truncated control packets leave `queuedCb->data` (as well as stack variables `enableByte` and `terminationReason` in `controlReceiveThreadFunc()`) uninitialized prior to invoking client `ListenerCallbacks`.
