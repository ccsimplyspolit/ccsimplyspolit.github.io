0x01 // Technical Specification & Remediation Patch

# Missing Resource ID Validation and Cross-Endpoint REST Path Traversal in acceptDisputeClaim, updateInvoiceAutoReminder, and updateShipmentTracking in paypal/agent-toolkit

- **CVD ID**: `CVD-2026-PAYPAL-AGENT-001`
- **Target Program**: HackerOne `paypal` (Paid Bounty Scope `638296` — `PayPal SDK (paypal/agent-toolkit)`)
- **Repository**: `https://github.com/paypal/agent-toolkit`
- **Vulnerable File**: `typescript/src/shared/parameters.ts (lines 342, 502, 574), typescript/src/shared/functions.ts (lines 454, 1205-1209, 1280-1285), python/paypal_agent_toolkit/shared/invoices/parameters.py (line 282), python/paypal_agent_toolkit/shared/tracking/parameters.py (line 48)`
- **Weakness**: `CWE-20 / CWE-22 / CWE-285`
- **Severity**: `High (CVSS 8.1)`

## Summary

I identified an input validation and REST path-traversal vulnerability across both the TypeScript and Python implementations of `paypal/agent-toolkit`. While other resource identifiers in the toolkit are constrained by strict regular expressions in `regex.ts` / `regex.py`, three mutating tool handlers—`acceptDisputeClaim` (`dispute_id` in TypeScript), `updateInvoiceAutoReminder` (`reminder_configuration_id` in TypeScript and Python), and `updateShipmentTracking` (`tracking_number` in TypeScript and Python)—interpolate unvalidated, unencoded strings directly into authenticated PayPal REST API URLs (`POST` and `PUT`). In `acceptDisputeClaimParameters` (`typescript/src/shared/parameters.ts`, lines 573-576), `.regex(DISPUTE_ID_REGEX)` was mistakenly attached to `note` instead of `dispute_id`.

## Root Cause Analysis

1. **Misplaced Regex on `acceptDisputeClaimParameters` (`typescript/src/shared/parameters.ts`, lines 573-576)**:
```typescript
export const acceptDisputeClaimParameters = (context: Context) => z.object({
  dispute_id: z.string(),
  note: z.string().regex(DISPUTE_ID_REGEX, "Invalid PayPal Dispute ID").describe("A note about why the seller is accepting the claim"),
});
```
And in `typescript/src/shared/functions.ts` (lines 1280-1285):
```typescript
const url = `${client.getBaseUrl()}/v1/customer/disputes/${params.dispute_id}/accept-claim`;
const response = await axios.post(url, { note: params.note }, { headers, params });
```
2. **Missing Regex & URL Encoding on `reminder_configuration_id` and `tracking_number`**:
In `updateInvoiceAutoReminder` (`PUT /v2/invoicing/reminders/${reminder_configuration_id}`) and `updateShipmentTracking` (`PUT /v1/shipping/trackers/${transaction_id}-${tracking_number}`), neither Python nor TypeScript validates or URL-encodes the path parameter before issuing an authenticated `PUT` request with the merchant's OAuth2 `Bearer` token.

## Steps to Reproduce

Run the standalone verification harness in `verify_batch6_paid_ai.py` (`test_02_paypal_agent_toolkit_path_traversal`):
```bash
python verify_batch6_paid_ai.py -v
```
- **BEFORE PATCH**: Passing `dispute_id = '../../../v2/checkout/orders/8XY12345678901234/capture#'` resolves the `POST` target URL to `https://api.paypal.com/v2/checkout/orders/8XY12345678901234/capture`.
- **AFTER PATCH**: `DISPUTE_ID_REGEX`, `REMINDER_ID_REGEX`, and `TRACKING_NUMBER_REGEX` plus `encodeURIComponent` / `urllib.parse.quote` reject any traversal characters.

## Suggested Remediation

```diff
--- a/typescript/src/shared/parameters.ts
+++ b/typescript/src/shared/parameters.ts
@@ -1,4 +1,4 @@
 export const updateInvoiceAutoReminderParameters = (context: Context) =>
   z.object({
-    reminder_configuration_id: z.string().describe('The ID of the auto reminder configuration to update.'),
+    reminder_configuration_id: z.string().regex(INVOICE_ID_REGEX, "Invalid PayPal Reminder Configuration ID").describe('The ID of the auto reminder configuration to update.'),
     type: z.enum(['BEFORE_DUE', 'AFTER_DUE']),
```

## Impact

A prompt-injected LLM agent restricted via `configuration.actions` (e.g., granted only `disputes.update`, `invoicing.reminders.update`, or `shipping.tracking.update`) can traverse out of the intended endpoint path and issue authenticated `POST` or `PUT` requests to arbitrary PayPal REST API endpoints using the merchant's live OAuth2 access token.
